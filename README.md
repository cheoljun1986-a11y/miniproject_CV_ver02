# WebXR Hidden Ninja v2

브라우저(WebXR)만으로 **ARCore 공간추적 + 실세계 오클루전 + 2D 영상의 3D 공간 복원**을
검증하는 AR 숨바꼭질 미니프로젝트. 설치 없이 Android Chrome에서 HTTPS 주소만 열면 동작한다.

- 공개 데모: <https://cheoljun1986-a11y.github.io/miniproject_CV_ver02/>
- CPU 동적 가림 모드: <https://cheoljun1986-a11y.github.io/miniproject_CV_ver02/?occlusion=cpu>
- 공간 복원 모드: <https://cheoljun1986-a11y.github.io/miniproject_CV_ver02/?depth=cloud>

---

## 1. 프로젝트 개요

Ninja(닌자)를 현실 공간 한 곳에 숨기고, 사용자가 직접 걸어다니며 찾는 AR 게임이다.
게임 자체가 목적이라기보다, **폰 한 대(WebXR/ARCore)만으로 어디까지 되는지**를 검증하는
feasibility 테스트에 가깝다. 특히 컴퓨터비전 관점에서 핵심은:

> **움직이는 카메라의 2D 영상 → 3D 공간으로 복원하고, 그 위에 가상 물체를 정합·가림 처리한다.**

## 2. 핵심 아이디어: 2D 영상 → 3D 공간

```
[카메라 2D 영상 + 폰 센서(IMU)]
        │  ← ARCore 담당 (depth-from-motion / SLAM)
        ▼
[6DoF 카메라 포즈]  +  [픽셀별 깊이맵(depth map)]
        │  ← 우리 담당 (역투영 unprojection)
        ▼
[각 깊이 픽셀 → 3D 월드 좌표]  →  누적/복셀화  →  3D 공간(포인트클라우드)
        │
        ▼
[그 위에 Ninja 배치 · 실세계 물체로 가림(occlusion)]
```

- **ARCore**: 여러 각도의 2D 프레임과 관성센서로 카메라 위치와 깊이를 추정한다.
- **우리 코드**: 그 깊이를 카메라 투영행렬·포즈로 3D 점으로 되돌리고(역투영), 누적한다.
  즉 순수 RGB로 직접 포토그래메트리를 하는 게 아니라, **ARCore가 준 깊이를 3D로 복원**한다.

## 3. 기술 스택

- **WebXR** `immersive-ar` (Android Chrome + ARCore)
- **three.js 0.180** (렌더링, WebXR 매니저, 내장 depth-sensing 오클루전)
- WebXR 기능: `hit-test`, `depth-sensing`, `dom-overlay`, (옵션) `anchors`, `local-floor`
- **정적 호스팅**: GitHub Pages (백엔드 없음). CDN(three.js)만 외부 의존.
- 테스트: Node.js `node:test` (순수 로직 단위 테스트 42개)

## 4. 진행 내역 (구현 완료)

### 4-1. 공간추적 + 숨바꼭질 (hit-test 기반)
- ARCore 6DoF viewer pose로 실시간 위치추적 (HUD에 x/y/z, 이동경로, 최대변위 표시)
- 20초 스캔 동안 **화면 중앙 광선(hit-test)** 이 맞은 표면 점을 0.25초 간격·22cm 이상
  간격으로 성기게 수집 → 그중 **수평면(바닥·책상 윗면)** 을 우선 후보로
- 후보 중 한 곳(정면에서 벗어난 1~8m 지점 선호)에 Ninja를 13% 투명도로 숨김
- 화면 중앙 조준 후 `SCAN` → 거리 ≤5m, 정면 ±12°면 `DETECTED!`
- `다시 숨기기`, `+20초 스캔`, 기준점 저장 → 복귀 오차(위치 m / 자세 deg) 측정

### 4-2. 스캔 점 시각화
- 20초 스캔 동안 저장되는 후보 점마다 AR 씬에 마커를 찍어 실시간으로 보여준다.
- 🟢 초록 = 수평면(닌자를 숨길 수 있는 곳), 🟠 주황 = 그 외 표면 점.
- "스캔은 전체 맵이 아니라 중앙 광선 점을 성기게 줍는다"는 동작을 눈으로 확인할 수 있다.

### 4-3. 실세계 오클루전 (depth-sensing, GPU)
- `depth-sensing`(`gpu-optimized`)으로 ARCore 깊이맵을 매 프레임 받음.
- three.js 내장 depth 메시가 실세계 깊이를 depth buffer에 기록(색은 안 그림) →
  현실 물체보다 뒤에 있는 Ninja 픽셀이 depth test로 가려진다.
- HUD에 `가림 GPU` 표시. depth 미지원 기기에서는 자동으로 꺼지고 기존처럼 동작(graceful fallback).
- **정적 vs 동적**: 매 프레임 실시간 depth이므로 손·사람 같은 **움직이는** 물체까지 가릴 수
  있는 유일한 방식이다. (정적 물체는 아래 복셀 방식으로도 가능)
- ⚠️ 갤럭시 S26 Ultra의 Chrome에서는 이 요청이 선택되지 않아 HUD에
  `depth usage unavailable`, `depth format -`가 표시되는 것을 확인했다. 즉 휴대폰이 깊이를
  전혀 계산하지 못하는 것이 아니라, 브라우저가 이 **GPU 전달 방식**을 세션에 제공하지 않은 것이다.

### 4-4. CPU 깊이 동적 가림 (`?occlusion=cpu`) — 신규
- 갤럭시에서 실제로 제공되는 `cpu-optimized` 깊이를 JavaScript로 읽어 `80 × 60` 격자의
  3D 삼각형 메시로 바꾼다. 최대 꼭짓점은 4,800개, 삼각형은 9,322개다.
- 이 메시는 화면에 색을 칠하지 않는다(`colorWrite: false`). 대신 실제 표면의 거리만
  **깊이 버퍼(depth buffer)** 에 먼저 기록한다. 이후 Ninja를 그릴 때 더 멀리 있는 픽셀은
  깊이 검사에서 탈락하므로 손이나 상자 뒤의 부분이 보이지 않는다.
- 쉽게 비유하면, 카메라 영상 위에 보이지 않는 3D 가림막을 실제 손·물체 모양대로 놓고 그 뒤에
  있는 Ninja만 지우는 방식이다.
- 깊이 차이가 `20cm`보다 큰 세 점은 하나의 삼각형으로 연결하지 않는다. 손 가장자리와 먼 벽을
  긴 면으로 잘못 이어 화면의 넓은 부분이 가려지는 현상을 줄이기 위한 장치다.
- Ninja는 hit-test가 찾은 실제 바닥·벽 표면에 놓이므로 측정 깊이와 거의 같다. ARCore 깊이의
  작은 오차만으로 Ninja 전체가 표면 뒤라고 판정되지 않도록, 가림 메시만 카메라에서 `5cm`
  뒤로 미는 **depth bias(깊이 여유값)** 를 적용한다. 더 가까운 손·물체와의 큰 거리 차이는
  그대로 남기 때문에 실제 가림 동작은 유지된다.
- 배치 지점의 행렬에서 **표면 normal(표면이 향하는 방향)** 을 계산하고, 그 방향이 카메라 반대쪽이면
  뒤집는다. Ninja는 바닥·책상에서는 `2cm`, 벽·경사면에서는 카메라 쪽으로 `12cm` 떨어뜨려 실제
  표면 안에 박히지 않게 한다. 이때 계산된 최종 좌표 하나를 화면 렌더링과 SCAN 거리·각도 판정에
  함께 사용하므로, 보이는 위치와 게임이 탐지하는 위치가 어긋나지 않는다. 전역 depth bias를 더
  키우지 않아 손·책의 정밀한 가림 여유도 보존한다.
- 스마트폰 부하를 줄이기 위해 메시 갱신은 최대 약 `15회/초`(`66ms` 간격)로 제한하고 배열과
  GPU 버퍼를 재사용한다. 새 깊이가 `250ms` 동안 오지 않으면 낡은 가림막을 숨긴다.
- HUD의 `가림 CPU · 삼각형 N`으로 메시가 실제 생성되는지 확인할 수 있다. `N=0`이면 CPU 모드는
  선택됐지만 현재 사용할 수 있는 깊이 표면이 없다는 뜻이다.
- ⚠️ 코드·자동 테스트는 완료했으며 갤럭시 S26 Ultra에서 손과 물체 가림 품질은 실기기 검증이 필요하다.

### 4-5. 3D 공간 복원 — 포인트클라우드 (`?depth=cloud`)
- 이 프로젝트의 컴퓨터비전 핵심. `?depth=cloud`로 켜면 `cpu-optimized` 깊이를 쓴다.
- 매 프레임 깊이맵을 성긴 격자로 샘플 → 각 픽셀을 **뷰어 포즈 + 투영행렬로 월드 좌표에
  역투영**(수직거리 기준) → 5cm 복셀로 중복 제거하며 누적.
- 이 누적 데이터는 아래 **운영자 뷰(4-5)에서 복셀로 시각화**된다. (초기엔 게임 화면에 원시
  점을 직접 그렸으나 화면이 지저분해, 지금은 **게임 화면에선 점을 그리지 않고 데이터만
  쌓는다**.) HUD에 누적 개수 `점 N` 표시.
- 실측(초기 원시 점 렌더 시): 상단 벽=분홍, 하단 바닥=파랑으로 **높이 구조가 일관되게** 나와,
  역투영이 정상 동작함을 확인.
- ⚠️ 미터 단위 정확도(실제 표면에 붙는지)는 "시차(parallax) 테스트"로 실기기 확인 필요.

### 4-6. 복셀 재구성 + 운영자(서버) 3D 뷰 (`?depth=cloud`)
- 누적된 포인트클라우드를 관측 횟수 기준(3회 이상 히트)으로 solid 복셀로 재구성 —
  일회성 depth 노이즈를 걸러내고, 최대 2만 복셀로 캡.
- `운영자 뷰` 버튼을 누르면 같은 화면에서 별도 캔버스로 전환되어, **오빗 카메라
  (`OrbitControls`)** 로 복원된 복셀 공간·Ninja가 숨은 위치(빨강 구)·플레이어 이동 경로
  (파랑 선)를 위에서 내려다보며 확인할 수 있다. `게임으로`를 누르면 AR 화면(트래킹 유지)
  으로 복귀.
- HUD `점 N`은 solid 복셀이 쌓이기 시작하면 원시 포인트 수 대신 그 값을 표시한다.
- ⚠️ 복셀 기반 **정적 오클루전**(베개·장난감·기둥 뒤에 Ninja를 숨기고 가리는 것)은 아직
  미구현 — Phase 2 후속 작업으로 남겨둔다. 동적 손 가림은 GPU 모드(4-3) 또는 새 CPU 모드
  (4-4)가 담당한다.

## 5. 문제 원인과 해결 과정 — 발표용 설명

### 문제

Ninja가 실제 손이나 물건 뒤에 있어도 계속 화면 위에 보였다. WebGL은 카메라 영상만 보고는
손이 Ninja보다 가까운지 알 수 없다. 현실 물체의 거리 정보가 렌더러의 깊이 버퍼에 들어와야
앞뒤 관계를 판단할 수 있다.

### 진단

기본 URL은 `gpu-optimized` 깊이만 요청했다. 갤럭시 S26 Ultra에서 HUD가
`depth usage unavailable`을 표시했으므로 그 세션에는 depth-sensing이 활성화되지 않았다.
반면 `?depth=cloud`에서는 `cpu-optimized` 깊이로 수만 개의 점이 만들어졌다. 이를 통해
**ARCore 깊이 계산은 동작하지만 WebXR가 GPU 방식은 제공하지 않고 CPU 방식만 제공한다**고 판단했다.

### 해결

브라우저가 자동으로 해주지 못한 GPU 가림을 애플리케이션이 CPU 깊이로 직접 만든다.

1. 깊이맵의 각 샘플을 카메라 투영행렬과 현재 자세로 3D 월드 좌표에 역투영한다.
2. 이웃한 점을 삼각형으로 연결하되 깊이가 갑자기 변하는 경계는 연결하지 않는다.
3. 삼각형의 색은 그리지 않고 깊이만 기록한다.
4. 그 뒤 Ninja를 렌더링하면 실제 물체보다 먼 Ninja 픽셀이 자동으로 제거된다.

### 왜 기존 포인트클라우드를 그대로 사용하지 않았나?

`?depth=cloud`는 방을 돌아다니며 점을 **누적**하여 정적인 공간 지도를 만드는 모드다. 이미 지나간
손 위치까지 남을 수 있어 움직이는 손 가림에는 맞지 않는다. CPU 가림 모드는 누적하지 않고 최신
깊이만 짧게 유지하므로 손의 움직임을 따라간다.

## 6. 세 개의 depth 모드

WebXR는 세션당 depth 모드를 하나만 쓸 수 있어, URL로 구분한다.

| | 기본 URL | `?occlusion=cpu` | `?depth=cloud` |
|---|---|---|---|
| depth usage | `gpu-optimized` | `cpu-optimized` | `cpu-optimized` |
| 하는 일 | three.js 내장 가림 | 앱이 만든 동적 메시 가림 | 포인트클라우드 공간 복원 |
| 동적 손 가림 | 브라우저 지원 시 가능 | 가능, 실기기 검증 필요 | 불가(과거 점을 누적) |
| HUD 표시 | `가림 GPU` 또는 unavailable | `가림 CPU · 삼각형 N` | `점 N` |
| 갤럭시 현재 결과 | GPU depth unavailable | 새 검증 대상 | CPU depth 정상 확인 |

`?depth=cloud&occlusion=cpu`처럼 두 값을 동시에 넣으면 CPU 가림을 우선한다. 두 작업을 동시에
실행해 스마트폰 부하가 커지는 것을 막기 위한 규칙이다.

## 7. 실행 / 테스트 방법

**기기 요건**: ARCore Depth 지원 Android + 최신 Chrome + HTTPS. (데스크톱은 미지원 안내 표시)

1. **갤럭시 CPU 가림 테스트**: `?occlusion=cpu` URL → START AR → HUD에서
   `depth usage cpu-optimized`와 `가림 CPU · 삼각형 N` 확인 → Ninja 앞에 책이나 상자를 둔 뒤
   손을 천천히 좌우로 움직여 가림 영역이 따라오는지 확인.
2. **GPU 가림 비교**: 기본 URL → START AR → `depth usage unavailable`이면 이 기기의 브라우저가
   GPU 방식을 제공하지 않는 것이므로 CPU 가림 URL과 결과를 비교한다.
3. **공간 복원 테스트**: `?depth=cloud` URL → START AR → 걸어다니며 방을 비추기(게임 화면은
   점 없이 깔끔) → HUD `점 N`(복셀 수)이 늘어나는지 확인 → **`운영자 뷰`** 버튼으로 복원된
   복셀 공간·닌자 위치(빨강)·이동 경로(파랑)가 실제와 맞는지 확인.
4. **게임 플레이**: 20초 스캔 → Ninja 자동 숨김 → 걸어서 탐색 → 중앙 조준 후 SCAN →
   DETECTED!. `다시 숨기기`로 반복.
5. **추적 안정성**: 특정 위치에서 `기준점 저장` → 3~5m 이동/360° 회전 → 같은 자리로 복귀 →
   `복귀 오차 확인` → 위치/각도 오차 기록.

### 로컬 실행
```bash
python -m http.server 8000
# http://localhost:8000  (단, WebXR는 HTTPS 또는 실기기 필요)
node --test tests/*.test.mjs   # 단위 테스트 42개
```

## 11. 제한 / 주의

- ARCore Depth 미지원 기기에서는 오클루전·포인트클라우드가 동작하지 않는다(게임은 정상).
- CPU 가림은 깊이 해상도와 약 15Hz 갱신률의 영향을 받으므로 빠른 손동작에서 가장자리가 늦게
  따라올 수 있다. 투명·반사 물체와 카메라에 아주 가까운 손은 ARCore 깊이 결손이 생길 수 있다.
- 오클루전/역투영의 실기기 기하 정확도는 아직 검증 중이다.
- Ninja 위치는 현재 `local` 좌표계 고정(anchor 미사용)이라, 오래 이동하면 미세 드리프트 가능.
- 아직 MediaPipe 손동작은 WebXR와 결합되지 않았고, SCAN 버튼이 그 자리를 대신한다.
