- 작성일: 2026-08-26

- 결과물: 저장소 루트의 단일 HTML 파일
- 주 자료: `webxr_3d_reconstruction_explained.pptx`, 주한별 교수 Computer Vision 11·12·13강, 현재 프로젝트 구현

## 1. 커뮤니케이션 목표

발표가 끝났을 때 청중은 다음 문장을 이해할 수 있어야 한다.

> 픽셀은 방향만 주고, 깊이는 거리를 주며, 카메라 포즈는 그 점을 방의 공통 좌표로 옮긴다. 이 월드 점을 여러 프레임에서 융합하면 3D 공간이 되고, 현실의 특정 장소를 지속적으로 추적하려면 앵커가 필요하다.

발표자는 쉬운 비유에만 의존하지 않고 `K`, 카메라 포즈, 역투영, 삼각측량, 재투영 오차, SfM, 복셀·TSDF의 관계를 실제 숫자로 설명할 수 있어야 한다.

## 2. 검토한 표현 방식

### A. 긴 기술 문서

스크롤형 글과 수식을 중심으로 구성한다. 내용 검색과 복습에는 좋지만 발표 화면으로 사용하면 한 화면의 정보량이 많고 PPT 변환이 어렵다.

### B. 정적인 16:9 슬라이드 묶음

PPT와 가장 비슷하지만 쉬운 설명과 교수님 질문에 대비한 상세 수식을 동시에 담기 어렵다. 상세 내용을 넣으면 슬라이드가 과밀해진다.

### C. 발표 화면과 상세 설명을 결합한 인터랙티브 스토리 — 채택

각 장은 먼저 큰 그림과 한 문장 결론을 보여준다. `쉽게 이해`와 `숫자로 확인` 내용을 같은 장 안에서 단계적으로 열어 볼 수 있게 한다. 발표 중에는 큰 그림만 사용하고, 질문이나 개인 학습 때 숫자 계산과 수식을 펼친다. 각 장이 독립적인 16:9 구성을 가지므로 나중에 PPT로 옮기기 쉽다.

## 3. 산출물과 파일 구조

최종 파일명은 `webxr_3d_reconstruction_guide.html`로 한다. 외부 빌드 도구 없이 브라우저에서 직접 열리는 단일 HTML로 작성한다.

- HTML, CSS, JavaScript를 한 파일에 포함한다.
- 외부 프레임워크와 네트워크 요청에 의존하지 않는다.
- 현재 게임 HTML과 코드를 변경하지 않는다.
- 데스크톱 발표 화면과 모바일 복습 화면에 모두 대응한다.
- 인쇄 시 각 장이 한 페이지에 가깝게 분리되도록 print 스타일을 제공한다.

## 4. 서사 구조

전체 흐름은 `질문 → 좌표계 → 숫자 계산 → 복원 → 프로젝트 적용 → 한계` 순으로 누적한다.

1. **한 장의 사진에는 왜 거리가 없는가** — 같은 광선 위의 여러 점이 같은 픽셀에 맺힌다.
2. **세 좌표계를 구분한다** — 이미지, 카메라(내 좌표), 월드 좌표.
3. **월드 좌표는 방에 놓는 가상의 자다** — WebXR `local` reference space와 원점.
4. **카메라 내부값 K가 픽셀을 방향으로 바꾼다** — 640×480, `fx=fy=600`, `cx=320`, `cy=240`.
5. **깊이를 합치면 카메라 3D 좌표가 된다** — `(440,300)`, `2.0m` → `(0.4,-0.2,-2.0)m`.
6. **포즈를 곱하면 월드 좌표가 된다** — 실제 4×4 행렬 → `(3.0,1.3,0.9)m`.
7. **내 좌표를 어떻게 참고하는가** — 카메라→월드와 월드→카메라의 반대 변환.
8. **한 카메라가 움직여 두 눈이 된다** — `f=600px`, `B=0.20m`, `d=60px` → `Z=2.0m`.
9. **시각 정보와 IMU가 포즈와 미터 스케일을 만든다** — VIO/SLAM, 드리프트와 보정.
10. **전통적인 SfM은 무엇을 하는가** — 대응점, RANSAC, E/F, 두 뷰 포즈, 삼각측량, PnP, BA.
11. **이 프로젝트는 SfM 전체를 직접 구현하지 않는다** — ARCore와 애플리케이션의 책임 경계.
12. **월드 점을 쌓으면 포인트클라우드가 된다** — 프레임별 역투영과 공통 좌표 누적.
13. **복셀과 TSDF가 노이즈를 줄인다** — 반복 관측, 자유공간 카빙, 표면 융합.
14. **좌표값과 앵커는 역할이 다르다** — 현실 위치의 지속 추적과 런타임 보정.
15. **실패 사례를 예측한다** — 흰 벽, 반복 무늬, 반사·투명 물체, 짧은 이동, 먼 거리, 동적 물체.
16. **30초 최종 설명과 예상 질문** — 발표자가 그대로 말할 수 있는 요약.

## 5. 핵심 시각 요소

각 장에는 한 개의 주 시각만 둔다. 장식용 이미지보다 관계를 설명하는 도식을 우선한다.

- 픽셀과 카메라 광선 도식
- 이미지/카메라/월드 좌표계 전환 도식
- 카메라 내부행렬 `K`의 숫자 계산
- 카메라 좌표와 월드 좌표를 연결하는 4×4 행렬
- 두 카메라 위치, 베이스라인, 시차의 삼각측량 도식
- ARCore 담당 영역과 애플리케이션 담당 영역을 나눈 파이프라인
- 포인트 → 복셀 → TSDF 표면의 단계적 비교
- 원시 좌표 저장과 앵커 추적의 시간 흐름 비교

시각 요소는 HTML/CSS/SVG로 구성하되 축 방향과 부호를 일관되게 유지한다. WebXR 예제에서는 `+X=오른쪽`, `+Y=위`, `−Z=앞`을 사용하고, 교수님 강의의 전통적인 CV 좌표계 `+Z=앞`, `+y=아래`와의 차이를 별도 표기로 명시한다.

## 6. 상세 정보 노출 방식

각 장의 기본 화면은 다음 세 요소만 먼저 보여준다.

1. 결론형 제목
2. 핵심 도식
3. 발표자가 말할 한두 문장

`숫자로 확인`을 열면 해당 장의 입력값, 계산 순서, 결과, 단위가 나타난다. `교수님 질문 대비`에는 용어의 엄밀한 정의와 오해하기 쉬운 지점을 짧게 넣는다. 상세 영역을 닫아도 핵심 흐름을 이해할 수 있어야 한다.

## 7. 정확성 원칙

- `START AR` 순간 휴대폰이 수학적으로 정확한 절대 원점이 된다고 단정하지 않는다. WebXR 런타임이 세션 시작 위치 근처에 `local` reference space를 제공한다고 설명한다.
- 가속도계가 베이스라인을 단독으로 정확히 측정한다고 설명하지 않는다. 카메라 특징점과 IMU의 visual-inertial fusion으로 미터 단위 포즈를 추정한다고 설명한다.
- “정렬이 필요 없다” 대신 ARCore가 프레임 간 등록을 제공하므로 애플리케이션이 별도의 ICP를 수행하지 않는다고 설명한다.
- 이 프로젝트가 전통적 incremental SfM을 직접 구현했다고 주장하지 않는다. ARCore가 포즈와 깊이를 제공하고, 프로젝트가 역투영과 공간 융합을 수행한다고 구분한다.
- 카메라 깊이는 광선의 유클리드 길이가 아니라 프로젝트 코드가 사용하는 view `−Z` 방향의 깊이로 계산한다.
- 원시 월드 좌표의 장기 고정을 보장하지 않는다. 물리적 위치를 유지할 때 앵커 pose를 프레임마다 다시 조회한다고 설명한다.

## 8. 상호작용과 발표 조작

- 마우스 휠과 위·아래 키로 장을 이동한다.
- 화면에 현재 장 번호와 전체 장 수를 작게 표시한다.
- 숫자 예제는 단계 버튼으로 한 계산씩 진행한다.
- 수식과 상세 설명은 키보드로도 열고 닫을 수 있는 네이티브 `details`를 사용한다.
- 자동 재생, 반복 애니메이션, 소리는 사용하지 않는다.
- `prefers-reduced-motion`을 존중한다.

## 9. 시각 스타일

로컬 참고 PPT의 교육용 톤을 계승하되 그대로 복제하지 않는다.

- 밝은 배경과 짙은 남색 본문
- 파랑: 카메라·이미지 정보
- 보라: 포즈·좌표 변환
- 주황: 깊이·삼각측량
- 초록: 월드 좌표·완성된 복원
- 빨강: 실패 조건·주의점

제목은 결론형 문장으로 쓰고, 장마다 카드 여러 개를 나열하지 않는다. 큰 도식 하나와 짧은 설명을 중심으로 구성한다. 본문은 발표 화면에서 읽을 수 있도록 충분히 크게 유지한다.

## 11. 검증 기준

### 내용 검증

- 모든 행렬과 숫자 예제를 수동 역산해 입력 픽셀로 재투영되는지 확인한다.
- CV 좌표계와 WebXR 좌표계의 부호가 섞이지 않았는지 확인한다.
- ARCore와 애플리케이션의 책임 경계가 모든 장에서 동일하게 표현되는지 확인한다.
- 로컬 PPT와 교수님 자료의 핵심 흐름이 빠짐없이 반영됐는지 확인한다.

### 화면 검증

- 데스크톱 1440×900과 1366×768에서 주요 내용이 한 화면에 들어오는지 확인한다.
- 모바일 390×844에서 가로 스크롤과 겹침이 없는지 확인한다.
- 모든 단계 버튼, `details`, 키보드 이동이 동작하는지 확인한다.
- 브라우저 콘솔 오류가 없는지 확인한다.
- 인쇄 미리보기에서 장 구분이 유지되는지 확인한다.

## 12. 완료 조건

- 단일 HTML 파일이 로컬에서 직접 열린다.
- 발표 모드만 보아도 전체 설명이 이어진다.
- 실제 숫자 예제에서 픽셀 → 카메라 좌표 → 월드 좌표가 계산된다.
- 전통적 SfM과 현재 WebXR/ARCore 파이프라인의 차이가 명확하다.
- 간단 설명과 심화 설명이 함께 존재하지만 기본 화면은 과밀하지 않다.
- 향후 각 장을 PPT 한 장으로 옮길 수 있는 독립적인 구조를 가진다.
