# CPU WebXR 깊이 가림 설계

작성일: 2026-08-25  
대상 브랜치: `cj_develop`

## 1. 목적

갤럭시 S26 Ultra의 브라우저가 WebXR 깊이를 `cpu-optimized` 방식으로만 제공하는 경우에도, 카메라 앞의 손이나 실제 물체가 뒤쪽의 닌자를 자연스럽게 가리도록 한다.

현재 기본 모드는 `gpu-optimized` 깊이만 요청한다. 이 기기에서는 해당 기능이 선택되지 않아 HUD에 `depth usage unavailable`, `depth format -`가 표시되고, 실제 물체의 깊이가 렌더러 깊이 버퍼에 기록되지 않는다. 따라서 닌자가 항상 실제 물체 위에 그려진다.

새 기능은 CPU 깊이 데이터로 색상이 없는 삼각형 메시를 매 프레임에 가깝게 갱신하고, 닌자보다 먼저 깊이 버퍼에만 그려 이 문제를 해결한다.

## 2. 범위

### 포함

- `?occlusion=cpu` 실험 모드 추가
- CPU 깊이 맵을 낮은 해상도의 동적 삼각형 메시로 변환
- 메시의 색상은 그리지 않고 깊이만 기록
- 깊이 경계에서 잘못 이어진 삼각형 제거
- CPU 깊이 미지원 또는 일시적인 데이터 누락 시 안전하게 기능만 비활성화
- HUD에 선택된 가림 모드와 생성된 삼각형 수 표시
- 순수 계산 로직의 자동 테스트 및 갤럭시 실기기 확인 절차

### 제외

- 기존 기본 GPU 가림 방식의 동작 변경
- `?depth=cloud` 포인트클라우드/복셀 작업자 화면의 변경
- 정적 복셀을 이용한 장기 누적 가림
- 네이티브 Android ARCore 앱 전환
- VGGT/모노큘러 깊이 모델 도입
- 빠르게 움직이거나 카메라에 지나치게 가까운 손에 대한 완벽한 픽셀 단위 분할

## 3. 사용자 접속 방식과 모드 우선순위

세 모드는 동시에 실행하지 않는다.

| URL | 동작 |
|---|---|
| 기본 주소 | 기존 `gpu-optimized` 가림 요청 |
| `?depth=cloud` | 기존 CPU 포인트클라우드/복셀 모드 |
| `?occlusion=cpu` | 새 CPU 동적 깊이 가림 모드 |

두 파라미터를 동시에 전달한 비정상 URL에서는 `occlusion=cpu`를 우선한다. 모드 선택은 별도의 순수 함수로 분리하여 테스트한다. 이 규칙은 한 세션에서 포인트클라우드 생성과 동적 가림 메시 생성을 동시에 수행해 스마트폰 부하가 커지는 것을 막는다.

CPU 가림 모드의 WebXR 세션은 `depth-sensing`을 선택 기능으로 요청하면서 다음 환경 설정을 사용한다.

```js
{
  usagePreference: ['cpu-optimized'],
  dataFormatPreference: ['float32', 'luminance-alpha']
}
```

브라우저가 깊이를 제공하지 않아도 AR 세션과 게임 자체는 계속 동작한다.

## 4. 선택한 구현 방식

### CPU 깊이 삼각형 메시

각 XR 프레임에서 `XRFrame.getDepthInformation(view)`로 얻은 깊이 맵을 고정 크기 격자로 샘플링한다. 각 샘플은 기존 `depthSampleToWorld()` 계산을 사용해 카메라 픽셀 좌표와 깊이값에서 월드 좌표로 변환한다.

인접한 네 점으로 이루어진 각 격자 셀에서 최대 두 개의 삼각형을 만든다. 다음 조건을 만족하지 않는 삼각형은 인덱스 목록에 넣지 않는다.

- 모든 꼭짓점의 깊이가 유효하고 설정된 최소·최대 거리 안에 있어야 한다.
- 한 삼각형 안의 `최대 깊이 - 최소 깊이`가 `0.20m` 이하여야 한다.

두 번째 규칙은 손의 윤곽과 먼 배경을 하나의 면으로 연결하는 긴 삼각형을 막는다. `0.20m`는 최초 실기기 튜닝값이며 설정 파일의 상수로 둔다.

메시는 다음 재질 속성을 사용한다.

```js
{
  colorWrite: false,
  depthWrite: true,
  depthTest: true,
  side: THREE.DoubleSide
}
```

즉, 카메라 영상의 색은 그대로 보이고 실제 표면의 깊이만 WebGL 깊이 버퍼에 기록된다. 닌자는 이 메시보다 나중에 렌더링되므로 실제 물체 뒤에 있는 픽셀이 깊이 검사에서 탈락한다.

### 다른 방식과 비교

1. **CPU 삼각형 메시 — 이번 구현**: 현재 코드의 좌표 변환 로직을 재사용할 수 있고 디버깅과 테스트가 비교적 쉽다. 다만 JavaScript에서 깊이 샘플을 순회하므로 해상도와 갱신률에 제한이 필요하다.
2. **CPU 깊이 텍스처 + 전용 셰이더**: 더 조밀하고 효율적으로 만들 가능성이 있지만 XR 카메라 보정, 텍스처 업로드, 깊이 비교 셰이더가 필요해 초기 구현 위험이 크다.
3. **네이티브 ARCore Depth API**: 장기적으로 가장 안정적인 선택이 될 수 있지만 웹 배포가 아닌 Android 앱으로 제품 구조를 바꿔야 한다.

## 5. 코드 구조

### 새 모듈

- `src/cpu-depth-occluder.js`
  - Three.js `BufferGeometry`와 깊이 전용 메시를 소유한다.
  - 미리 할당한 위치·인덱스 버퍼를 재사용한다.
  - XR 프레임에서 깊이 데이터를 읽고 메시를 갱신한다.
  - 세션 종료 또는 오류 시 메시를 숨긴다.
- `src/cpu-occlusion-math.js`
  - 유효 깊이 판정과 삼각형 연결 여부를 결정하는 순수 함수만 둔다.
  - Three.js나 브라우저가 없는 Node 테스트에서 검증한다.

### 변경 모듈

- `src/main.js`
  - URL 모드를 한 번 해석한다.
  - CPU 가림 모드에서만 `CpuDepthOccluder`를 만들고 렌더 직전에 갱신한다.
  - 기존 GPU 모드와 클라우드 모드의 경로는 유지한다.
- `src/config.js`
  - 격자 크기, 갱신 간격, 거리 범위, 최대 깊이 차이 상수를 추가한다.
- `src/ui.js`
  - `가림 CPU`, 깊이 사용 방식/포맷, 현재 유효 삼각형 수를 표시한다.

## 6. 성능 제한

초기값은 다음과 같이 제한한다.

- 격자: `80 x 60` (최대 4,800개 꼭짓점)
- 갱신 간격: `66ms` 이상 (최대 약 15회/초)
- 유효 거리: 기존 깊이 범위와 맞춘 최대 `6m`
- 삼각형: 최대 `(80 - 1) x (60 - 1) x 2 = 9,322개`

TypedArray와 `BufferGeometry`는 시작할 때 한 번 할당하고 프레임마다 새 배열을 만들지 않는다. 갱신하지 않는 프레임에는 마지막 메시를 유지한다. 경계구를 매번 계산하지 않도록 `frustumCulled = false`를 사용한다.

실기기에서 프레임 저하나 발열이 크면 가장 먼저 격자를 `64 x 48`로 낮춘다. 품질 조정은 상수 변경으로 가능하게 한다.

## 7. 데이터 흐름

1. 사용자가 `?occlusion=cpu`로 접속한다.
2. AR 시작 시 브라우저에 `cpu-optimized` 깊이를 요청한다.
3. XR 렌더 루프가 현재 뷰의 CPU 깊이 정보를 가져온다.
4. 깊이 샘플을 월드 좌표로 변환한다.
5. 유효하지 않거나 깊이 차이가 큰 삼각형을 제외한다.
6. 깊이 전용 메시의 위치·인덱스 버퍼를 갱신한다.
7. 깊이 메시를 먼저, 닌자를 나중에 렌더링한다.
8. 실제 물체보다 뒤에 있는 닌자 픽셀은 깊이 검사로 보이지 않게 된다.

## 8. 오류 처리

- `getDepthInformation()`이 없거나 예외를 던지면 메시를 숨기고 다음 프레임을 계속 처리한다.
- 특정 프레임의 깊이 데이터가 없으면 이전 메시를 무기한 사용하지 않고 짧은 만료 시간 뒤 숨긴다. 오래된 손 위치가 화면을 계속 가리는 현상을 막기 위해 만료 시간은 `250ms`로 한다.
- 유효 삼각형이 하나도 없으면 메시를 숨긴다.
- 새 XR 세션이 시작되거나 기존 세션이 종료되면 깊이 메시 상태와 HUD 카운터를 초기화한다.
- CPU 가림이 불가능해도 닌자 게임, 카메라 화면, 배치 기능은 정상 작동해야 한다.

## 9. 검증

### 자동 테스트

- URL 모드 선택과 두 파라미터 충돌 시 우선순위
- 3개 깊이가 모두 유효한 경우의 삼각형 생성
- `0`, `NaN`, 범위 밖 깊이를 포함한 삼각형 제외
- 깊이 차이가 `0.20m`를 넘는 삼각형 제외
- 최대 인덱스/삼각형 수 제한
- HUD의 CPU 모드 및 삼각형 수 표시
- 기존 전체 테스트 회귀 확인

### 갤럭시 S26 Ultra 실기기 통과 조건

1. `?occlusion=cpu`로 접속했을 때 HUD의 depth usage가 `cpu-optimized`로 표시된다.
2. 닌자보다 카메라에 가까운 상자나 책을 두면 겹치는 부분의 닌자가 보이지 않는다.
3. 손을 천천히 좌우로 움직이면 손 뒤의 닌자가 가려지고, 손이 이동하면 가림 영역도 따라간다.
4. 손이나 물체 가장자리와 먼 배경 사이에 큰 삼각형 가림막이 생기지 않는다.
5. 깊이를 지원하지 않는 브라우저에서도 AR 화면이 중단되지 않는다.

빠른 손동작, 투명·반사 물체, 매우 가까운 거리에서는 ARCore 깊이 자체의 지연이나 결손 때문에 가장자리가 일부 어긋날 수 있다. 이는 첫 버전의 허용 한계로 명시한다.

## 10. 완료 기준

- 기본 URL과 `?depth=cloud`의 기존 동작 및 테스트가 유지된다.
- `?occlusion=cpu`에서 CPU 깊이 메시가 닌자보다 먼저 깊이 버퍼에 기록된다.
- 깊이 누락 및 세션 전환 시 오래된 가림 메시가 남지 않는다.
- 자동 테스트가 통과한다.
- 갤럭시 S26 Ultra에서 위 실기기 통과 조건을 확인할 수 있는 배포 URL을 제공한다.
