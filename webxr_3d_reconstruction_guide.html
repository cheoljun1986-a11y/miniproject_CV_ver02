01 · 시작 질문

한 장의 사진에는 거리가 없다

같은 픽셀 뒤에는 1m, 2m, 4m의 점이 모두 겹쳐 있을 수 있다.

사진은 3D 공간을 2D 평면에 눌러 담는다.

픽셀 주소만으로는 물체가 광선 위 어디에 있는지 알 수 없습니다. 그래서 3D 복원에는 반드시 깊이 또는 여러 시점의 관측이 필요합니다.

교수님 질문 대비

투영은 여러 3D 점을 하나의 2D 점으로 보내는 many-to-one 관계입니다. 단일 영상만으로 절대 깊이를 유일하게 복구할 수 없는 이유입니다.

02 · 좌표계

이미지·카메라·월드 좌표는 서로 다른 주소다

이미지 좌표는 사진 안의 픽셀 주소입니다.

카메라 좌표는 지금 휴대폰을 원점으로 한 ‘내 좌표’입니다.

월드 좌표는 세션 동안 방 전체가 공유하는 주소입니다.

같은 현실 점도 어느 기준에서 말하느냐에 따라 숫자가 달라진다.

+X 오른쪽+Y 위−Z 앞
CV 좌표계는 보통 +Z를 앞, +y를 아래로 설명합니다. WebXR 예제는 +Y가 위, −Z가 앞입니다.

03 · 기준

월드 좌표는 방에 놓는 가상의 자다

현실에 숫자가 붙어 있는 것이 아니라, WebXR 런타임이 기준 공간을 제공한다.

월드 좌표는 방에 놓은 가상의 3차원 자다.

프로젝트는 WebXR의 local reference space를 사용합니다. 원점은 세션 시작 위치 근처에 런타임이 정하며, 좌표 단위는 미터입니다.

GPS나 북쪽 기준의 절대좌표가 아닙니다. 현재 휴대폰이 이 자에서 어디에 있고 어느 방향을 보는지가 카메라 포즈입니다.

정확히 말하면

“START AR 순간 폰이 정확한 (0,0,0)”은 쉬운 설명입니다. 실제 native origin과 축 정렬은 런타임이 정하고 WebXR은 일관된 reference space를 제공합니다.

04 · 방향

K가 픽셀을 카메라 광선으로 바꾼다

예제 영상은 640 × 480이고 중심은 (320, 240)입니다.

fx = fy = 600 px라고 하면 픽셀 (440, 300)은 중심에서 오른쪽 120px, 아래 60px입니다.

xₙ = (440 − 320) / 600 = 0.2
yₙ = −(300 − 240) / 600 = −0.1
광선 방향 ≈ (0.2, −0.1, −1)
카메라 내부행렬 K
K = [ 600   0   320 ]
    [   0 600   240 ]
    [   0   0     1 ]

05 · 깊이

방향과 깊이를 합치면 카메라 3D 점이 된다

방향 벡터를 깊이만큼 늘리면 3D 위치가 된다.

(0.2, −0.1, −1) × 2.0 m
= (0.4, −0.2, −2.0) m

즉 지금 카메라 기준으로 오른쪽 40cm, 아래 20cm, 앞쪽 2m에 표면이 있습니다.

왜 광선 길이가 정확히 2m가 아닌가

이 프로젝트는 depth를 광선의 유클리드 길이가 아니라 카메라 view −Z축에 수직인 깊이로 사용합니다. 그래서 광선의 z가 −2가 되도록 스케일합니다.

06 · 변환

카메라 포즈를 곱하면 월드 주소가 된다

카메라의 월드 위치가 (1.0, 1.5, 0.5)m이고, 앞쪽이 world +X를 향하도록 회전했다고 하겠습니다.

Xworld = Tworld←camera · Xcamera
(0.4, −0.2, −2.0) → (3.0, 1.3, 0.9) m

픽셀 (440, 300): 아직 화면 속 주소만 알고 있습니다.

4×4 카메라→월드 행렬
Tworld←camera = [ 0  0 −1  1.0 ]
                [ 0  1  0  1.5 ]
                [ 1  0  0  0.5 ]
                [ 0  0  0  1.0 ]

07 · 내 좌표

내 좌표와 월드 좌표는 서로 왕복할 수 있다

스캔 점을 방에 저장:
카메라 좌표 → 월드 좌표

월드의 닌자를 화면에 표시:
월드 좌표 → 카메라 좌표 → 픽셀

나와 닌자의 거리:
두 월드 위치의 차이 벡터 크기

내 좌표는 현재 관측을 설명하고, 월드 좌표는 시간과 프레임을 연결한다.

수식으로 보기
Xworld = Rwc · Xcamera + Cworld
Xcamera = Rcw · (Xworld − Cworld)

08 · 삼각측량

움직인 카메라는 두 눈처럼 깊이를 만든다

카메라가 20cm 이동하고 같은 특징점이 60px 어긋났다고 하겠습니다.

f = 600 px
B = 0.20 m
d = 440 − 380 = 60 px

Z = fB / d = 600 × 0.20 / 60 = 2.0 m

시차가 크면 가깝고, 시차가 작으면 멀다.

거리별 시차 비교

1m에서는 120px, 2m에서는 60px, 6m에서는 20px입니다. 먼 곳은 작은 픽셀 오차에도 깊이가 크게 흔들립니다.

09 · 추적

시각 정보와 IMU가 미터 단위 포즈를 만든다

카메라는 모서리·무늬 같은 특징점이 화면에서 어떻게 움직였는지 봅니다. IMU는 자이로와 가속도계로 빠른 회전·이동 변화를 측정합니다.

시각 정보와 IMU를 함께 결합해야 빠르면서도 장시간 덜 틀리는 추적이 된다.

가속도계가 이동거리 20cm를 혼자 재는 것이 아니다. 카메라 특징점과 IMU를 함께 융합해 미터 단위 포즈를 추정한다.
드리프트는 왜 생기나

센서 노이즈, 특징점 부족, 빠른 움직임 때문에 작은 추정 오차가 시간에 따라 쌓입니다. 새 관측으로 과거 지도를 다시 맞추면서 일부 오차를 교정합니다.

10 · SfM

전통적 SfM은 카메라와 구조를 함께 복원한다

사진만 주어졌을 때 카메라 포즈와 3D 점을 번갈아 확장하고 함께 보정하는 과정이다.

특징점→대응점→ RANSAC
Essential / Fundamental→초기 두 뷰 포즈→ 삼각측량→PnP로 새 카메라→Bundle Adjustment

삼각측량은 포즈가 알려진 카메라들에서 3D 점을 구합니다.

PnP는 알려진 3D 점과 새 영상의 2D 점으로 새 카메라 포즈를 구합니다.

Bundle Adjustment는 모든 카메라와 3D 점을 함께 조정해 재투영 오차를 줄입니다.

목적함수
min Σ || π(Pc, Xn) − xc,n ||²
카메라와 3D 점을 동시에 최적화

11 · 역할 분담

ARCore와 우리 코드의 책임은 다르다

ARCore / WebXR가 제공

카메라 영상과 IMU 기반 6DoF 카메라 포즈

depth-from-motion 기반 픽셀별 깊이맵

reference space, hit-test, anchor API

우리 코드가 수행

픽셀 + 깊이의 역투영(unprojection)

카메라 좌표 → 월드 좌표 변환

포인트 누적, 복셀화, TSDF 공간 융합

“ARCore가 포즈와 깊이를 만들고, 우리 코드는 역투영과 월드 변환으로 3D 공간을 편다.”

12 · 누적

월드 점을 누적하면 포인트클라우드가 된다

매 프레임의 깊이 점을 그 순간의 카메라 포즈로 월드에 옮기면 서로 다른 시점이 한 방 안에 겹쳐진다.

프레임마다 생긴 3D 점을 공통 월드 좌표에 쌓는다.

이 프로젝트에서는 ARCore가 프레임 간 카메라 등록을 제공하므로 애플리케이션이 별도의 ICP 정렬을 수행하지 않습니다.

다만 포즈나 깊이에 오차가 있으면 점이 두껍게 번지고 허공에 유령점이 생깁니다.

프로젝트 구현

depth-math.js가 한 점을 역투영하고, depth-cloud.js와 키프레임 지형 경로가 월드 점을 누적합니다.

13 · 융합

복셀과 TSDF가 노이즈를 표면으로 정리한다

포인트클라우드는 관측된 점을 그대로 모읍니다.

복셀은 3D 공간을 작은 칸으로 나누고 여러 키프레임에서 반복 관측된 칸을 신뢰합니다.

TSDF는 표면 근처의 부호 있는 거리와 카메라에서 표면까지의 자유공간을 함께 누적합니다.

한 번 본 점보다, 여러 시점에서 같은 표면이라고 합의한 공간이 더 믿을 만하다.

TSDF의 부호

광선에서 표면 앞쪽은 자유공간, 표면 근처는 0 교차, 표면 뒤쪽은 반대 부호로 누적됩니다. 이를 통해 허공의 일회성 점을 지울 수 있습니다.

14 · 고정

좌표값 저장과 현실 장소 추적은 다르다

숫자만 저장

t₀ 닌자 좌표 (3.0, 1.3, 0.9) 저장

t₁ 추적 지도가 보정됨

결과 예전 숫자는 현실 위치와 어긋날 수 있음

앵커로 장소 추적

t₀ 현실의 이 지점을 anchorSpace로 등록

t₁ 매 프레임 최신 anchor pose 조회

결과 지도 보정에 맞춰 숫자 좌표도 갱신

앵커는 “이 숫자를 기억해”가 아니라 “현실의 이 장소를 계속 추적해”라는 요청이다.

15 · 한계

깊이가 실패하는 장면은 미리 예측할 수 있다

특징점 대응, 카메라 포즈, 깊이 추정 중 하나만 흔들려도 최종 월드 점이 틀어진다.

흰 벽

구별할 특징이 없어 프레임 사이 같은 위치를 찾기 어렵다.

반복 무늬

모두 비슷해 잘못된 대응점을 선택하기 쉽다.

유리·거울

반사와 투과 때문에 보이는 위치와 표면 위치가 다르다.

짧은 이동

시차가 작아 삼각형이 납작해지고 깊이 불확실성이 커진다.

먼 거리

같은 1px 오차가 훨씬 큰 미터 단위 깊이 오차로 확대된다.

움직이는 물체

장면이 정적이라는 가정을 깨서 서로 다른 위치가 한 점으로 매칭된다.

시연 팁: 0.5~5m 거리에서 천천히 옆으로 움직이고, 모서리·무늬가 있는 정적 표면을 충분히 비춘다.

16 · 정리

픽셀에서 월드까지 한 문장으로 연결된다

픽셀→광선→깊이→카메라 좌표→월드 좌표→3D 융합

30초 발표 대본

카메라의 픽셀은 방향만 알려주고 깊이는 알려주지 않습니다. ARCore는 여러 시점의 영상과 IMU를 결합해 카메라 포즈와 픽셀별 깊이를 추정합니다. 저희 코드는 픽셀을 광선으로 역투영하고 깊이를 적용해 카메라 좌표를 만든 뒤, 촬영 순간의 포즈를 곱해 월드 좌표로 변환합니다. 여러 프레임의 월드 점을 복셀이나 TSDF로 융합하면 방의 3D 구조가 만들어집니다. 현실의 특정 위치를 오래 유지할 때는 좌표값만 저장하지 않고 앵커를 사용합니다.
